# M0-02 对象识别与 Mask 真实链路结果

## 结论

M0-02 的工程链路已打通：Qt 打开图片后，后台线程使用 OpenCV 完成模型预处理，
ONNX Runtime 通过 CPU 执行真实 Mask R-CNN 推理；界面将每个实例 Mask 转成轮廓，
鼠标悬停会高亮，点击按 Mask 像素命中对象并保留完整分辨率 Mask。

模型效果不是“全部通过”。固定的 13 个点击探针中命中 9 个，整体命中率为 69.2%。
这证明交互和推理链可用，也证明单一 COCO 80 类 Mask R-CNN 不能覆盖产品要求。M0-03
需要引入人物/Alpha Matting，后续模型方案还需补服装、透明物体、小密集物体和开放词汇能力。

## 固定输入与环境

- 探针：`poc/evaluation/m0_02_click_probes.csv`，13 次点击、10 类产品对象，均来自
  M0-00 锁定的 Open Images 案例。
- 模型：`MaskRCNN-12-int8.onnx`，45,769,352 bytes，固定 SHA-256 见
  `poc/models/README.md`；阈值为 score 0.70、mask 0.50。
- 机器：Apple M4（10 CPU/10 GPU）、24 GB、macOS 26.3。
- 运行时：Qt Base 6.11.2、OpenCV 4.12.0、ONNX Runtime 1.29.0，
  `CPUExecutionProvider`。
- 原始 JSON、逐对象 PNG Mask 与轮廓叠加图保存在被 Git 忽略的
  `poc-results/20260908T065204Z-d6ab35b-m0-02/`；该目录由
  `make evaluate-m0-02` 自动生成，汇总见其中的 `summary.csv`。

## 耗时

13 次均为冷启动：每次重新加载模型并执行一张图，因此更接近当前 POC 界面的首次处理。

| 指标 | P50 | P95 | 最小–最大 | 平均 |
| --- | ---: | ---: | ---: | ---: |
| 纯推理 | 484 ms | 617 ms | 335–617 ms | 493 ms |
| 全链路 | 983 ms | 1111 ms | 802–1111 ms | 970 ms |

全链路还包含图片读取、约 0.4–0.5 秒的模型加载、OpenCV 预处理和 Mask 后处理。正式
架构应复用常驻 Session；M0-07 再测常驻模型、4K/20 对象、内存和交互帧时间。

## 自动化与人工检查

- `make test`：5 个 CTest 全部通过，包括原有依赖/后台任务测试、Mask 像素命中规则、
  Qt 画布悬停/点击测试，以及真实 OI-07 `cat` 推理和点击命中测试。
- 真实集成测试不是 stub：模型缺失、推理失败、中心点击未命中 `cat` 都会返回失败。
- 人工查看 OI-07 叠加图：猫的主体 Mask 和外轮廓位置正确；细毛/胡须未被低分辨率
  Mask 完整保留，属于后续 Matting 的处理范围。
- 错误呈现：模型缺失、图片解码错误和 ONNX Runtime 异常都会返回可理解的中文消息；
  没有候选时界面明确显示“未找到置信度 ≥ 70% 的对象”。

## 范围边界

- 本节点证明“真实检测 → 实例 Mask → 悬停 → 点击”能在 Qt 桌面端成立，不表示所有
  产品对象或精细边缘已经达标。
- 13 个探针是 M0-02 技术尖峰，不替代 M0-10 的无教程用户任务测试，也不替代 M0-11
  对完整 65 案例的最终 Go/No-Go 汇总。
- 模型卡写 MIT，而镜像元数据写 Apache-2.0；两者虽均宽松，发布前仍需人工复核并
  随安装包保留正确许可证文本。
