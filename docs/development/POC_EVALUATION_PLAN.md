# M0 POC 评测方案

> 版本：V0.1
> 固化日期：2026-09-08
> 对应任务：M0-00
> 清单：`poc/evaluation/corpus_manifest.csv`

## 1. 目的

本方案先固定样本、指标、硬件记录和决策阈值，再开始选择模型和实现 POC，避免用
临时挑选的“好看案例”证明技术可行。它服务于 M0 的 `GO / CONDITIONAL GO /
NO-GO` 决策，不是训练集，也不是可随产品分发的素材包。

任何人变更样本、阈值或排除规则时，必须先提升本方案版本，并在结果中同时保留
旧版本。评测完成后不能为了改善结果而删除失败样本。

## 2. 固定测试集

V0.1 共定义 65 个案例：41 个已经锁定到具体文件和 SHA-256，24 个通过数据集与
确定性选样规则锁定、获取后补充逐文件 SHA-256。

| 子集 | 数量 | 用途 | 当前状态 |
|---|---:|---|---|
| Open Images V7 Validation | 24 | 人物、服装、动物、普通对象、遮挡、重复对象、天空、简单/复杂背景和 20 对象候选 | 已锁定 ID、来源页、下载地址和 SHA-256 |
| TextOCR 0.1 Validation | 10 | 从极稀疏到超密集的 OCR、文字检测和版面 | 已锁定 ID、下载地址和 SHA-256；逐图归属待复核 |
| P3M-Net Demo | 7 | 人物、头发和细边缘的定性冒烟测试 | 已锁定提交、路径和 SHA-256；不能把示例输出当真值 |
| P3M-500-P | 8 | 人物 Alpha Matting 定量真值 | 按文件名排序前 8 项；待按协议获取并补校验和 |
| AM-2K | 4 | 动物毛发 Alpha Matting 真值 | 许可证表述冲突，人工复核前不得下载或使用 |
| Transparent-460 | 4 | 玻璃、透明/半透明对象 Alpha 真值 | 仅限非商业研究，不提交、不发布、不用于产品训练 |
| 项目自有/书面授权 | 8 | 中文文字、真实用户照片、烟/水、反射和极端背景 | 待采集；必须有权属/授权与隐私记录 |

### 覆盖要求

- 人物：单人、多人、全身、半身、遮挡、侧身、头发、婚纱/细边缘；
- 动物：猫、狗、马、牛、鸟，包含毛发、羽毛、浅景深和复杂背景；
- 服装：裙装、西装、运动服和大面积衣服，验证换色后的明暗/纹理/褶皱；
- 普通对象：汽车、摩托车、手机、相机、瓶子、书籍、重复货架对象；
- 场景：简单/复杂背景、天空、远景、路人、拥挤和前后遮挡；
- 半透明：婚纱、玻璃瓶、透明物体以及烟/水私有样本；
- 文字：极稀疏、道路标志、中等密度、超密集版面、英文和中文；
- 性能：所有功能样本保留原尺寸；从代表性图片确定性生成 3840×2160 性能副本，
  副本不得进入质量指标。

### 排除规则

仅允许因文件损坏、来源撤回、许可证失效、缺少所需真值或包含不应处理的敏感内容
而排除。排除必须记录案例 ID、理由、日期和替代案例；模型失败不是排除理由。

## 3. 数据、许可证和隐私边界

- [Open Images V7](https://storage.googleapis.com/openimages/web/factsfigures_v7.html)：
  Google 将标注以 CC BY 4.0 提供，图片列示为 CC BY 2.0；官方同时提示应逐图核验
  许可证。因此图片只进入本地评测缓存，清单保留原落地页，不把图片提交到 Git。
- [TextOCR 0.1](https://textvqa.org/textocr/dataset/)：标注数据为 CC BY 4.0，图片来自
  Open Images；逐图归属复核完成前只允许本地评测。
- [P3M-10k / P3M-Net](https://github.com/ViTAE-Transformer/P3M-Net)：仓库和数据集协议
  标示 MIT。Demo 图片仍需独立核验来源，因此只作本地定性测试；仓库中的示例 Alpha
  是模型输出，不是真值。
- [AM-2K](https://github.com/bruinxiong/animal-matting)：数据协议标为 MIT，但仓库说明
  同时写有仅研究用途并要求商业使用联系作者。结论冲突，人工复核前状态为阻塞。
- [Transparent-460](https://github.com/AceCHQ/TransMatting)：仅限非商业研究，禁止作为
  可分发资产、商业训练数据或发布测试包。
- 项目自有/私有图片必须记录拍摄者、被摄者授权、用途、保留期限和删除方式；不得
  上传云端，除非用户对具体图片和具体服务另行明确同意。

`poc/evaluation/data/` 与 `poc-results/` 已加入 `.gitignore`。模型、数据集、测试图片、
生成结果和可能含个人信息的日志默认不进入版本库。

## 4. 指标定义

### 4.1 对象识别与交互

- `Intended Object Success`：用户在预先标注的有效点击位置点击后，选中的语义对象
  是否为目标对象；重叠区单独统计，不混入普通点击。
- `Hover Latency`：分析完成后，从鼠标进入目标区域到轮廓可见的时间，记录 P50/P95。
- `Selection Latency`：点击到选中状态稳定的时间，记录 P50/P95。
- 自动分析记录首结果时间、完整结果时间、对象召回和误检数。

### 4.2 Mask 与 Alpha Matting

- 二值/实例 Mask：IoU、Boundary F-score，并按人物、衣服、动物、普通对象分组；
- Alpha Matting：SAD、MSE、Gradient、Connectivity；
- 另设盲评量表检查毛发缺失、锯齿、光晕、半透明错误和背景颜色污染；
- 没有真值的 P3M Demo 只能进入定性报告，不能计入定量平均值。

### 4.3 删除、移动和背景补全

- 分简单背景与复杂背景统计可接受率；
- 记录结构错乱、重复纹理、人物/文字幻觉、颜色接缝和阴影残留；
- 记录首预览与最终结果时间；每项必须可取消、可撤销并恢复原图。

### 4.4 衣服换色

- 衣服区域命中、非衣服泄漏、肤色/背景污染；
- 盲评明暗、纹理、褶皱和材质是否保留；
- 原颜色、目标颜色、Mask 版本和参数必须进入结果记录。

### 4.5 OCR 与文字修改

- 检测 Precision/Recall、字符错误率 CER、词错误率 WER；
- 中文与拉丁文字分别统计，旋转、透视和密集版面单独统计；
- 字体只要求给出近似候选，不能把无法验证的“完全一致”记为成功；
- 文字移除和重绘另做背景修复与视觉一致性盲评。

### 4.6 性能、内存和历史

- 统一使用 Release 构建，记录机器、操作系统、编译器、Qt/OpenCV/ONNX Runtime
  版本、推理执行提供程序、线程数和电源模式；
- 4K + 20 对象记录平移/缩放/拖动帧时间 P50/P95、峰值 RAM/显存、缓存命中、首屏、
  首次推理和二次推理；
- 50 步 Undo/Redo 必须比较初始、最终、全部撤销和全部重做的文档摘要与渲染摘要；
- 崩溃、数据损坏、不可撤销或静默改变原图均为硬失败。

### 4.7 用户理解度

至少 5 名没有 Photoshop 熟练经验的参与者，在不看教程的情况下完成抠图、删除、
移动和换色。记录任务完成率、首次动作、帮助次数、放弃原因和访谈反馈。

## 5. 预先锁定的判定阈值

| 项目 | GO | CONDITIONAL GO | NO-GO |
|---|---|---|---|
| 对象点击 | 普通有效点击成功率 ≥90%，重叠场景有可理解的候选切换 | 80%–<90%，且一次明确改进可验证 | <80%，或一次改进后仍无法稳定点击目标 |
| 实例 Mask | 各核心组 IoU ≥0.85 且 Boundary F ≥0.80 | 总体达到但一个非核心组未达标且有修正入口 | 人物/普通对象任一核心组明显未达标且无可用修正 |
| 人物/毛发 | 定量不明显劣于选定开源基线，盲评可接受率 ≥80% | 指标合格但一个细边缘组为 60%–<80% | 主体结构丢失、明显光晕，或可接受率 <60% |
| 删除/移动 | 简单背景 ≥80%，复杂背景 ≥60%，均可撤销 | 简单背景达标，复杂背景不足但已明确降级/云端路径 | 简单背景 <70% 或存在不可恢复破坏 |
| 衣服换色 | 区域与纹理盲评可接受率 ≥80% | 60%–<80% 且泄漏可通过 Mask 修正 | <60% 或频繁污染皮肤/背景 |
| OCR/文字 | 拉丁 CER ≤10%；中文 CER ≤15%；重绘可接受率 ≥80% | 仅一个语言/版面组未达标且产品可明确限制 | 常见清晰文字不可稳定识别或修改 |
| 4K 交互 | 拖动帧时间 P95 ≤33.3ms，悬停/选择 P95 ≤100ms，峰值 RAM ≤2.5GiB | 帧时间 33.3–50ms 或 RAM 2.5–4GiB，且优化路径明确 | P95 >50ms、RAM >4GiB 或频繁卡死/崩溃 |
| 50 步历史 | 100% 正确往返、无崩溃、原图未变 | 正确但内存增长需在 M1 限定 | 状态不一致、数据损坏或存在不可撤销步骤 |
| 硬件 | macOS arm64 与至少一台 Windows x64 通过 CPU 降级；GPU 能力按矩阵记录 | 核心路径通过，单个 GPU 提供程序需降级 | Windows/macOS 任一核心平台无可用路径 |
| 新手任务 | 4 项总完成率 ≥80% | 60%–<80%，问题可由一次交互修正验证 | <60%，或用户仍必须先理解图层/Mask/工具链 |
| 许可证/隐私 | 发布依赖、模型和云服务均有可接受的商业与隐私路径 | POC 数据仅本地研究且已有可替换商业路径 | 核心能力只能依赖不可商用或不可接受的数据上传 |

总体规则：全部 P0 核心项通过才可记 `GO`。点击对象、历史正确性、平台可运行路径和
许可证/隐私路径不能用其他高分抵消。`CONDITIONAL GO` 必须列出不超过一个评审周期
的补充 POC；触发任一核心 `NO-GO` 即停止进入 M1。

## 7. 结果目录与必需证据

每次评测写入 `poc-results/<UTC时间>-<git提交>/`，至少包含：

```text
run.json                 环境、版本、模型、执行提供程序和参数
cases.csv                每案例输入、输出、耗时、指标和失败原因
metrics.json             汇总及分组指标
artifacts/               Mask、Alpha、补全、换色和文字结果
logs/                    已去除敏感路径/文本的诊断日志
REPORT.md                结论、失败样本、限制和复现命令
```

结果不能只保存平均数，必须保留逐案例记录、失败图片引用和环境信息。私有样本产物只
保存本地受控目录，报告使用匿名案例 ID。
