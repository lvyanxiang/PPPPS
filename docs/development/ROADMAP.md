# PPPPS 对象驱动智能图像编辑器总里程碑

## 1. 目标与使用规则

本路线图把 `docs/project-initiation/` 中的全部功能点纳入 M0–M10。早期节点验证
“点击对象 → 选择目标 → 自动完成”的核心范式，后续节点逐步补齐基础编辑、人物、
场景、文字、生成式能力、专业能力、自动化和生态。某项不进入 V1，并不代表它从
总范围中删除。

固定技术方向：

- 桌面端：Qt 6；首选 Qt Widgets 专业桌面外壳 + 自定义画布视口；
- 语言与构建：C++20 + CMake；
- 传统图像处理：OpenCV；本地推理：ONNX Runtime；模型研发/导出可使用 Python + PyTorch；
- 渲染：POC 先建立可替换接口，再用数据选择 Qt Raster、Skia 或平台 GPU 后端；
- 平台：Windows 和 macOS，CPU 降级路径必须存在，GPU 路径按硬件能力启用；
- 编辑模型：原始资产不可变，所有对象、Mask、Transform、Adjustment 和 History 都可序列化、可重放、可撤销。

勾选规则：

1. `[x]` 只表示代码/文档产物已经存在，并且完成了该项要求的验证；
2. 每完成一个可交付切片，同时更新本文件与 `STATUS.md`；
3. 当前里程碑未通过验收闸门，不开始后续里程碑；
4. 同一功能在 POC 中只证明可行，在后续里程碑中仍需完成产品化；
5. 若需求改变，保留稳定功能编号，记录迁移/取消理由，不能直接静默删除。

## 2. 阶段映射

| 调研阶段 | 本路线图 | 结果 |
|---|---|---|
| Phase 0 技术验证 | M0 | POC 报告与 GO / CONDITIONAL GO / NO-GO |
| Phase 1 MVP | M1–M4 | 可保存、可导出、对象驱动的人物/背景编辑器 |
| Phase 2 智能编辑 | M5–M6 | 场景、文字、人像和增强能力 |
| Phase 3 生成式编辑 | M6 | 生成式填充、扩图、替换、重建与融合 |
| Phase 4 专业能力 | M7–M9 | 选择、Mask、图层、色彩、矢量、批处理和大文档 |
| Phase 5 生态 | M10 | PSD、插件、市场、第三方扩展和云同步 |

## M0 — Qt 桌面端 POC 与立项闸门

目标：在正式建设完整引擎前，验证对象交互、关键算法、4K 性能、历史稳定性和
桌面硬件兼容性。POC 可以使用替代实现，但必须保留可观测指标，不能用静态演示
冒充真实推理或编辑流水线。

### M0.0 验证基线

- [x] **M0-00** 建立 POC 测试集、许可/来源记录、基线硬件、指标定义和 Go/No-Go 判定表；覆盖人物、毛发、动物、服装、普通物体、遮挡、半透明、天空、文字、简单与复杂背景、4K 图片。
- [x] **M0-01** 建立 Qt 6 + C++20 + CMake POC 工程；验证 JPEG/PNG 解码、OpenCV、ONNX Runtime、后台任务、取消、进度、错误呈现和最小自动化测试链路。

### M0.1 对象识别与 Mask

- [ ] **M0-02** 完成“打开图片 → 自动检测主要对象 → 鼠标悬停轮廓高亮 → 点击命中对象 → 获得 Mask”的真实链路；记录按对象类型的命中率、推理时间和错误类型。
- [ ] **M0-03** 完成人物抠图与 Image/Alpha Matting 对比；单独评估头发、动物毛发、婚纱/玻璃等半透明边缘，并提供手工修正可行性结论。

### M0.2 目标驱动编辑

- [ ] **M0-04** 完成对象删除和对象移动；移动后原位置通过传统 Inpainting 或生成式补全恢复，记录背景复杂度、伪影、等待时间和回退行为。
- [ ] **M0-05** 完成衣服区域识别与换色；验证明暗、纹理和褶皱保持。
- [ ] **M0-06** 完成文字修改技术尖峰：文字检测 → OCR → 原字移除 → 字体近似 → 新字渲染；给出可产品化边界，而不是把所有字体精确匹配视为已解决。

### M0.3 工程可行性

- [ ] **M0-07** 验证 4K 图片 + 20 个语义对象的推理、悬停、选择和实时拖动；记录 P50/P95 帧时间、峰值内存/显存、缓存命中、低分辨率预览与最终高质量计算。
- [ ] **M0-08** 用 Command + 差量完成连续 50 次编辑的 Undo/Redo；验证往返后文档状态一致、内存有界、保存/重开后结果一致。
- [ ] **M0-09** 建立 Intel、AMD、NVIDIA 以及 Windows、macOS 兼容矩阵；至少验证 CPU 降级，记录可用推理/渲染后端、驱动问题和未覆盖硬件。
- [ ] **M0-10** 用无需教程的任务测试验证“点击对象 → 选择目标”是否可理解；至少覆盖抠图、删除、移动、换色并记录失败路径。
- [ ] **M0-11** 形成 `docs/development/POC_REPORT.md`，逐项给出证据、限制、许可证/云成本、风险处置和 `GO`、`CONDITIONAL GO` 或 `NO-GO` 结论。

验收闸门：八类 POC 均有可复现证据；4K/20 对象和 50 次历史测试完成；对象点击
交互对目标用户成立；关键模型许可证和本地/云成本路径可接受。`NO-GO` 时停止并
回到产品交互模型，不继续堆叠功能。

## M1 — 可演进的非破坏式核心

目标：把 POC 替代实现收敛为可测试、可保存、可扩展的编辑器骨架。

- [ ] **CORE-01 Document Model**：文档、画布、资产引用、版本、迁移和序列化。
- [ ] **CORE-02 Layer System**：像素层、对象层及稳定 Z 顺序的场景树基础。
- [ ] **CORE-03 Mask System**：二值/灰度/Alpha Mask、边界操作和组合。
- [ ] **CORE-04 Semantic Object System**：对象 ID、类型、名称、置信度、父子关系、源资产、Mask、Transform、Effects、Adjustments。
- [ ] **CORE-05 Transform System**：移动、缩放、旋转及统一坐标/命中测试。
- [ ] **CORE-06 History System**：Command Pattern、差量、事务、Undo/Redo、可重放和内存预算。
- [ ] **CORE-07 Tile System**：分块、脏区传播、多分辨率金字塔和大图调度。
- [ ] **CORE-08 Render Engine**：合成树、Alpha、预览质量级别、渲染后端抽象和色彩边界。
- [ ] **CORE-09 AI Task Orchestrator**：检测/分割/Matting/OCR/增强/补全任务编排、依赖、取消、进度、失败与回退。
- [ ] **CORE-10 Cache System**：CPU/显存预算、LRU/代价淘汰、磁盘缓存、模型缓存和可观测指标。
- [ ] **CORE-11** 分离 `app/ui`、`core/document`、`core/render`、`core/history`、`image`、`ai`、`storage` 与平台适配层，核心不得依赖具体窗口。
- [ ] **CORE-12** 建立单元、集成、Golden/像素差、基准、崩溃恢复和文档迁移测试基础设施。

验收闸门：可用最小 Qt UI 创建/打开文档，执行非破坏对象变换，保存并重开；核心
层可无 GUI 测试；同一命令可重放并稳定撤销。
